# PWA Escala de férias 2027 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publish a separate, installable GitHub Pages PWA for choosing 2027 vacations, with Apps Script as the only rule-validation and Google Sheets write service.

**Architecture:** A lightweight Vite/vanilla JavaScript PWA will render the friendly month/week interface and communicate with an Apps Script Web App. The Apps Script will read the protected `FÉRIAS-2027` spreadsheet, validate all business rules, authenticate sigla/PIN requests, update cells, and record audit events. No secrets or sheet credentials are shipped to GitHub Pages.

**Tech Stack:** Vite, vanilla JavaScript modules, CSS, Web App Manifest, Service Worker, Apps Script V8, Google Sheets/Properties Service, Node test runner.

**Spec:** `docs/specs/2026-10-04-pwa-ferias-2027.md`

## Global Constraints

- Repository: `anestesiahmtforms/ferias2027`.
- Application title: `Escala de férias 2027`.
- Use the SAHMT logo and responsive mobile-first layout.
- January and July remain visible but do not accept new choices in this round.
- Each sigla has a maximum of two weeks, counting existing markings.
- Only SIGLA 1 is available until every permitted week has an initial sigla.
- SIGLA 2 and SIGLA 3 become available only after the initial round is complete.
- Coincidence limit is at most two Monday–Friday working days, applied in the joint round.
- The browser never receives raw PINs, sheet IDs, or administrative secrets.
- Existing spreadsheet values, formatting, validation, and protections must be preserved.
- Every write and administrative change produces an audit record.
- Offline mode is read-only.

## Review Focus

- Two users submit the same vacancy nearly simultaneously; the second request must be rejected without overwriting the first. Test in Task 4.
- The final SIGLA 1 submission transitions the phase without rejecting the submission itself. Test in Task 3.
- An existing January/July value is counted toward the two-week cap but cannot be edited by a member. Test in Task 3.
- A malformed, replayed, or expired request must not write to the sheet. Test in Task 4.
- A stale cached PWA must show a version/update path and never submit using old rules. Test in Task 5.
